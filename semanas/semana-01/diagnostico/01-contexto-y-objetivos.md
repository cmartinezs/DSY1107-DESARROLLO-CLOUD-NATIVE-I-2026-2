# 1. Contexto y objetivos

## Contexto

Una organización pequeña necesita una herramienta interna para registrar y dar seguimiento a incidencias técnicas: problemas de acceso, errores de aplicaciones, fallas de equipos, solicitudes de soporte y otros eventos similares.

Actualmente estos casos se informan por mensajes informales, por lo que se pierde información y no existe una visión clara de qué incidencias están pendientes, cuáles están en proceso y cuáles fueron resueltas.

El equipo deberá proponer y construir una solución web mínima que permita gestionar estas incidencias.

---

## Objetivo general

Construir en equipo una aplicación fullstack sencilla que permita diagnosticar las competencias previas necesarias para abordar posteriormente prácticas cloud native sobre un sistema real.

## Objetivos específicos

Al finalizar la actividad, el equipo debería ser capaz de demostrar que puede:

- levantar requerimientos funcionales y no funcionales básicos;
- identificar actores, datos y reglas del problema;
- diseñar una arquitectura fullstack simple;
- justificar decisiones arquitectónicas iniciales;
- construir una interfaz web conectada a un backend;
- implementar una API con operaciones CRUD;
- persistir datos en una base de datos;
- trabajar colaborativamente utilizando Git;
- contenerizar los componentes del sistema;
- levantar la solución completa con Docker Compose;
- documentar cómo ejecutar y verificar la aplicación.

---

## Modalidad

El desarrollo será **grupal**.

Cada integrante debe participar activamente en el análisis, implementación, integración y explicación de la solución. El repositorio del equipo debe permitir observar contribuciones distribuidas entre sus integrantes.

Adicionalmente, cada estudiante deberá contestar en forma **individual y privada** el cuestionario definido para esta actividad.

---

## Alcance deliberadamente acotado

Este diagnóstico no busca evaluar quién construye la aplicación más grande. Se espera un producto pequeño pero completo.

Es preferible entregar:

- un CRUD completamente integrado;
- una arquitectura comprensible;
- una ejecución reproducible;
- documentación clara;

antes que incorporar autenticación avanzada, microservicios, mensajería, inteligencia artificial u otras funcionalidades que no son necesarias para demostrar las competencias requeridas.

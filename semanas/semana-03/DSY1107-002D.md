# DSY1107-002D · Semana 3

## Regla de arranque

No asumir que el plan de Semana 2 equivale a cierre. Los primeros 15 minutos reconstruyen evidencia: gateway operativo, actores OAuth2/OIDC, Authorization Code + PKCE, identidad local, tokens y 401/403. Se continúa desde el **último punto demostrable**.

## Secuencia recomendada

```text
checkpoint verificable
→ completar identidad local/PKCE si falta
→ access token vs ID token
→ 401/403 reproducibles
→ anatomía JWT
→ iss/aud/exp/scopes
→ JWT forense
→ política gateway/API
→ usuarios externos/CIAM
→ mapeo a proveedor cloud si prerrequisitos están cerrados
```

## Bloque A · recuperación activa

Un grupo dibuja actores; otro explica token; otro ejecuta gateway. No usar presentación. Las respuestas determinan cuánto puente se necesita.

## Bloque B · token como evidencia

Decodificar token local, identificar claims y discutir cuáles son declaraciones vs cuáles han sido verificadas.

## Bloque C · seguridad

Ejecutar matriz de acceso y ubicar el origen de cada rechazo. Introducir seguridad de API Manager solo después de comprender la política neutral equivalente.

## Bloque D · CIAM/cloud

Mapear usuario externo, cliente, IdP, scopes y API a las capacidades del entorno institucional disponible. La configuración concreta se documenta como implementación de conceptos ya defendidos.

## Criterio de cierre

Registrar explícitamente qué llegó a demostrarse. Si no se alcanza cloud, no marcarlo realizado. El siguiente inicio debe nombrar el checkpoint exacto, no «continuar Semana 3».

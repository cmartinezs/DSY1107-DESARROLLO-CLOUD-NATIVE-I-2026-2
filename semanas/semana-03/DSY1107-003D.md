# DSY1107-003D · Semana 3

## Punto de partida conservador

La última evidencia inequívoca de la sección dejó el laboratorio de API Gateway en progreso; OAuth2/OIDC fue trabajado conceptualmente, mientras starter, PKCE completo, matriz 401/403 y configuración real de identidad no deben darse por realizados sin evidencia posterior.

Por ello 003D **no comienza directamente en JWT/cloud**.

## Ruta de recuperación y avance

```text
gateway defendible
→ actores OAuth2/OIDC
→ Authorization Code + PKCE
→ starter de identidad local
→ access token / ID token
→ 401 / 403
→ JWT y claims
→ seguridad gateway/API
→ usuarios externos / CIAM
→ cloud según tiempo real
```

## Estrategia de clase

La recuperación no es repetir una presentación completa. Cada concepto se valida con una pregunta o demostración corta. Lo que el curso demuestra se da por recuperado; lo que no, recibe explicación y práctica inmediata.

## Gate antes de JWT

No avanzar a JWT aplicado mientras el grupo no pueda ubicar usuario, cliente, Authorization Server/IdP y Resource Server; explicar el propósito de PKCE; distinguir access token de ID token; y producir al menos un caso de acceso rechazado en el entorno local.

## Cuando se habilite JWT

Usar el laboratorio forense común: claims, `iss`, `aud`, `exp`, scopes y diferencia entre decodificación y verificación. Después trasladar la política al gateway/API Manager.

## Priorización si falta tiempo

Prioridad 1: gateway + OAuth/OIDC + identidad local.  
Prioridad 2: 401/403 + JWT/claims.  
Prioridad 3: mapeo cloud y usuario externo.

No sacrificar comprensión de los prerrequisitos para «alcanzar» nominalmente el último tema.

Persistir: último paso ejecutado con evidencia, conceptos defendidos, laboratorio funcionando/no funcionando, deuda exacta y comando/archivo/pregunta con que debe comenzar la sesión siguiente.

# Contenido extendido · Formativa y transferencia

Complementa [Formativa 1 y transferencia a RegistrApp](../04-formativa-y-transferencia.md).

## 1. Laboratorio antes que proyecto

Un laboratorio reduce variables y permite comprender el patrón.

RegistrApp sirve después para transferir la competencia a un contexto con más dependencias.

## 2. Qué significa transferir

Transferir no es copiar nombres de clases.

Significa identificar una necesidad equivalente y adaptar el patrón conservando sus principios.

## 3. Preguntas antes de tocar el proyecto

- ¿qué recurso debe protegerse?;
- ¿quién es el cliente?;
- ¿qué scope representa la operación?;
- ¿qué componente valida identidad?;
- ¿qué componente autoriza?;
- ¿qué evidencia demuestra el recorrido?

## 4. Formativa como diagnóstico

Una evaluación formativa debe revelar modelos mentales incorrectos.

Ejemplos:

- creer que ID Token sirve para cualquier API;
- creer que CORS autentica;
- creer que Gateway reemplaza al backend;
- creer que 401 y 403 son equivalentes.

## 5. Evidencia de transferencia

El incremento debe dejar:

- diagrama;
- configuración sanitizada;
- pruebas 401/403/2xx;
- commits;
- DevLog;
- deuda conocida.

## 6. Evitar alcance artificial

No agregar funcionalidades irrelevantes solo para hacer la entrega “más grande”.

La profundidad técnica del flujo seguro importa más que el volumen de CRUD.

## 7. Preparación de defensa

Cada integrante debería poder explicar:

- una decisión;
- una evidencia;
- una falla;
- una alternativa;
- un cambio hipotético.

## 8. Idea clave

Primero comprensión reproducible; después integración al proyecto real.

Escenario de la guía

Self-service B2B en un workforce tenant

La práctica usa Microsoft Entra External ID para colaboración B2B. El tercero se auto-registra y queda aprovisionado como Guest en el mismo workforce tenant. No es el flujo CIAM de un external tenant.

    B --> S[Self-service sign-up]
    S --> G[Guest]
    X[External tenant] --> C[CIAM / customer identity]

Modelo mental

El lifecycle que automatizamos

stateDiagram-v2
    [*] --> NoExiste
    NoExiste --> SignUp: usuario llega a SPA
    SignUp --> IdentityVerified: IdP valida identidad
    IdentityVerified --> Attributes: primer alta
    Attributes --> Guest: aprovisionamiento
    Guest --> SignIn: accesos posteriores
    SignIn --> Guest

Diagnóstico

No cambies cinco capas al mismo tiempo

  1. No aparece self-service: workforce tenant, permisos y External collaboration settings.
  2. No aparece el IdP: configuración de Identity Provider.
  3. No aparecen atributos: usuario ya existente o Page layout/user flow incorrecto.
  4. No se crea Guest: provisioning/user flow/política.
  5. Guest creado pero SPA falla: redirect URI/MSAL.
  6. Login funciona pero API falla: access token, issuer, audience o scope.
